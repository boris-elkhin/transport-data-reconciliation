# Сверка и обогащение логистических реестров: ETL-пайплайн на pandas

## 📌 О проекте

Проект представляет собой ETL-пайплайн для автоматической сверки ручных реестров подрядчиков с выгрузкой из автоматизированной системы 1С:TMS. Главная цель — привести «грязные» данные из двух разных источников к единому виду и обогатить фактические данные подрядчиков справочной информацией из 1С: маршрутами, типом груза и статусами заявок.

---

## Бизнес-проблема

В логистике предприятия данные о фактических поездках собираются в **ручных реестрах**, которые заполняются с ошибками. Эти файлы содержат:

1. **«Грязные» идентификаторы заявок** — опечатки, лишние символы (`А0012345`) и составные форматы (`ЦП/057762`, `79703 от 06.04`, `59756\nдоп`).
2. **Отсутствие справочных данных** — в реестрах нет адресов погрузки и разгрузки, типа груза и статуса заявки.

Выгрузка из **1С:TMS** содержит недостающие поля, но **тоже имеет неточности в номерах заявок**: буквы-приставки, пробелы внутри и ведущие нули.

Из-за этого прямое объединение таблиц по ID даёт лишь **~40% совпадений**, что приводит к ошибкам в биллинге, аналитике по маршрутам и контроле затрат.

---

## 🛠 Решение

Разработан пайплайн на `pandas`, который решает задачу в три этапа.

### 1. Двусторонняя нормализация

Номера заявок очищаются от мусора **как в отчёте 1С, так и в реестре подрядчиков**, приводясь к единому числовому формату:

- В отчёте убираются буквы-приставки (`А/a/а`), ведущие нули и пробелы внутри числа.
- В реестре дополнительно разбираются составные форматы: слэш, «от», скобки и переносы строк.

### 2. Двухэтапный алгоритм объединения (Fallback Merge)

- **Этап 1** — точное объединение по `Номер + Дата заявки`.
- **Этап 2** — для строк, не прошедших первый этап, применяется запасное объединение по связке `Дата + ТС + Код цеха`.

### 3. Обогащение данных

К реестру из отчёта 1С:TMS подтягиваются:

- `Адрес отправления` и `Адрес получения` (маршрут)
- `Тип груза`
- `Статус заявки`
- `Подразделение`

---

## 📊 Метрики качества объединения

| Метрика | Значение |
|---|---:|
| Всего строк в реестре | 800 |
| Объединено по ID + Дата (этап 1) | 736 (**92%**) |
| Объединено по fallback-признакам (этап 2) | 64 (**8%**) |
| Потеряно строк | **0%** |

> Благодаря двухэтапному алгоритму процент успешной сверки вырос с ~40% до 100%.

## 💡 Ключевые инсайты (на примере цеха 57)

После успешного объединения данных была построена аналитика, выявившая следующие закономерности.

### 1. 📈 Выраженная сезонность (коэффициент 4×)

- **Пик:** сентябрь — 200 часов (33 заявки).
- **Провал:** февраль — 50 часов (11 заявок).
- **Вывод:** подрядчики вынуждены держать парк под пиковый спрос, закладывая издержки простоя в тарифы в межсезонье.

### 2. 💰 Дисбаланс в тарифах подрядчиков

- **«ООО Подрядчик В»** выставляет счёт на **30% выше среднего** по цеху: 2 803 руб./час против 2 149 руб./час, при этом занимая 23% объёма работ и 30% затрат.
- **Потенциал экономии:** перераспределение его объёма на других подрядчиков даст экономию **~200 тыс. руб.**

### 3. 🛣 Аномальные маршруты

- Маршрут **«Склад 1 — Склад 2»** занимает в среднем **7,8 часа на рейс**, что в 1,3 раза выше среднего по цеху (5,9 часа).
- **Вывод:** требуется аудит логистики этого направления: расстояний, времени погрузки и разгрузки, а также простоев.

### 4. 📦 Структура грузов

- **43,7%** всего времени работы техники приходится на перевозку **песка** (612 часов).
- Ещё **40,1%** — на **грунт и щебень**.
- **Вывод:** 84% часов работы техники приходится на три типа груза, что делает их ключевыми направлениями для приоритетного контроля тарифов.

## Как запустить

### 1. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 2. Генерация данных

Скрипт создаст папку `data/` с тремя Excel-файлами, содержащими реалистичные паттерны «грязи»: опечатки, лишние символы и переносы строк.

```bash
python generate_data.py
```

### 3. Запуск пайплайна

Основной скрипт выполнит очистку, двухэтапное объединение, агрегацию и визуализацию. Результаты сохранятся в папку `output/`.

```bash
python main.py
```

### 🛠 Стек технологий

- **Python 3.10+**
- **Pandas** — очистка, `.agg()`, `merge`, `reindex`, `indicator`, `validate`
- **NumPy** — векторизованные операции
- **Matplotlib / Seaborn** — визуализация с выделением аномалий цветом и референсными линиями
- **Openpyxl** — работа с Excel

### 🎯 Что демонстрирует проект

- Умение работать с грязными реальными данными и приводить их к единому виду.
- Понимание бизнес-контекста.
- Знание приёмов pandas (`.agg()` с именованными кортежами, `validate`, `indicator`, `reindex`, `fillna`).
- Инженерная культура: разбивка на функции, вынос констант, проверки качества данных и контроль целостности строк после объединения.
- Визуализация уровня middle-аналитика: подписи значений, референсные линии и цветовое выделение аномалий.

### ⚠️ Дисклеймер

Все данные в репозитории синтетические. Они генерируются скриптом `generate_data.py` на основе реальных бизнес-паттернов и намеренно содержат «грязь» для демонстрации работы ETL-пайплайна. Реальные данные компании не раскрываются.
